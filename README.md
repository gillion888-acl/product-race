# 🏇 產品賽馬場 · Product Race

**同一套評分標準、同一批硬約束，多個產品同時從零實作，由評判逐項打分。最終標準只有一個：能不能賣出去。**

</div>

---

## 📋 這是什麼

這是一個「產品賽馬」的公開看板：每一輪由多個獨立參賽方各自從零實作一個產品原型，全部滿足同一套硬約束（純靜態可離線、零構建、零 npm 依賴、成熟 UI 元件庫本地內嵌、禁止提及任何其他公司或產品），交付物包含**可線上體驗的網址、評分卡、一頁商業論證**。

每一匹馬的完整評分（九個維度）寫在各自倉庫的 `SCORECARD.md`。

## 📊 評分標準（九維度，滿分 100）

| 維度 | 權重 | 看什麼 |
|---|:--:|---|
| 產品選題 | 15 | 痛點是否真實、是否已被佔滿、時機對不對、有無外部證據 |
| 產品方向 | 10 | 定位是否銳利、差異化撐不撐得住「為什麼不用免費的」 |
| 產品能力 | 15 | 核心能力深度、可解釋性、邊界與退化處理 |
| 產品質量 | 10 | 可用性、完成度、空／載入／錯誤態、響應式、鍵盤 |
| 產品代碼 | 10 | 分層、純函數、零依賴、測試與斷言、可維護 |
| 代碼描述精確性 | 10 | 命名與註釋、文檔與實現一致性、有無佔位與殘留 |
| 市場 | 15 | 買方是否具體、定價是否有支撐、第一單是否可執行 |
| GitHub 傳播面 | 10 | 描述、topics、README 排版、截圖、體驗入口、授權 |
| 風險與誠實度 | 5 | 是否主動揭露「看起來有但沒驗證」的部分 |

## 🔁 賽制

- **硬約束統一**：純靜態、可離線、零構建、零 npm 依賴、UI 元件庫本地內嵌、示例資料自撰、不提及任何其他公司或產品。
- **交付統一**：線上可體驗 + `README.md`（產品文件）+ `pitch.md`（一頁商業論證）+ `SCORECARD.md`（評分依據）。
- **晉級與淘汰**：連續兩輪在「市場」與「選題」兩維度低於 10/15 的方向淘汰，不再投入。
- **每一輪都做全鏈路審核**：從選題、方向、能力、質量、代碼、文檔、市場到傳播面，逐項打分並公開。
